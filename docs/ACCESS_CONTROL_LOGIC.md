# دليل منطق الصلاحيات والأدوار في نظام MAVEX
## MAVEX Access Control & Role-Based Permissions Logic (RBAC)

---

## 1. مقدمة وهيكل الصلاحيات (Overview)

يعتمد نظام **MAVEX** للإدارة الصناعية على معمارية حماية ثنائية الطبقات (**Dual-Layer RBAC Architecture**):
1. **طبقة الواجهة الأمامية (Frontend Layer):** عبر مكونات `<ProtectedRoute>`، التحقق من الصلاحيات في `<Sidebar>`، ودالة `canAccess()` داخل `AuthContext`.
2. **طبقة الخادم (Backend Layer):** عبر وسيط المصادقة `authenticate.js` (فحص توكن الـ JWT وقاعدة بيانات MongoDB) ووسيط التصريح `authorize.js` (التحقق من الدور والقسم).

---

## 2. مصفوفة الأدوار والصلاحيات (Role Matrix)

يحتوي النظام على ثلاثة مستويات رئيسية للأدوار:

| الدور البرمجي (`role`) | المسمى الوظيفي | الصلاحيات العامة | نطاق الأقسام المصرح بها |
| :--- | :--- | :--- | :--- |
| **`admin`** | **مدير النظام / الإدارة العليا** | صلاحيات كاملة ومطلقة (Full Access). يستطيع عرض وتعديل وحذف أي سجل، إنشاء مستخدمين، والوصول للرقابة الإدارية. | **كافة الأقسام (8 أقسام) + صفحة المخالفات الإدارية** |
| **`department_manager`** | **مدير قسم صناعي / تنفيذي** | إدارة كاملة لعمليات قسمه (إضافة وتعديل واعتماد الأوامر والتقارير)، مع إمكانية استعراض لوحة المؤشرات العامة. | **القسم التابع له فقط** (لوحة التحكم العامة مفتوحة للاطلاع) |
| **`department_member`** | **مهندس / فني تشغيل / موظف** | تسجيل المتابعات اليومية، قراءة التعليمات، وتحديث مراحل أوامر التشغيل دون صلاحية التعديل المالي أو الحذف. | **القسم التابع له فقط** |

## 3. تفاصيل ما يراه كل حساب في النظام (Screen-by-Screen Visibility)

### 3.1. حساب مدير النظام (`admin@mavex.com`)
- **ما يظهر في القائمة الجانبية (Sidebar):**
  - ✅ **لوحة التحكم العامة** (`/`)
  - ✅ **المكتب الفني** (`/technical-office`)
  - ✅ **إدارة الإنتاج** (`/production`)
  - ✅ **التخطيط والمستودعات** (`/planning-warehouse`)
  - ✅ **الصيانة والتشغيل** (`/maintenance`)
  - ✅ **الحسابات والمالية** (`/finance`)
  - ✅ **مراقبة الجودة** (`/quality`)
  - ✅ **السلامة والصحة المهنية** (`/safety`)
  - 👑 **إدارة المخالفات والرقابة** (`/violations-admin`) *(حصري للأدمن فقط)*
- **ما يستطيع تنفيذه داخل الصفحات (Actions):**
  - إنشاء، تعديل، وحذف أوامر الإنتاج.
  - إضافة ومسح سجلات الفحص ومحاضر الجودة.
  - إنشاء أوامر صيانة طارئة ووقائية وإسنادها للفنيين.
  - إدخال الحركات المخزنية والتسويات الجردية وتعديل أسعار الخامات.
  - إصدار قرارات المخالفات وتحديد الجزاءات الإدارية.
  - تسجيل القيود المحاسبية ومسيرات الرواتب.

### 3.2. حسابات مديري الأقسام (`department_manager`)
مديرو الأقسام مقيدون وظيفياً بالأقسام الخاصة بهم:

#### أ. مدير مراقبة الجودة (`quality@mavex.com`)
- **ما يراه:**
  - لوحة التحكم العامة (`/`): للاطلاع على كفاءة المصنع الإجمالية وترتيب قسمه.
  - قسم مراقبة الجودة (`/quality`): السجل الكامل للعينات، نتائج الفحص المرحلي والنهائي، ومؤشرات الرفض والقبول.
  - باقي الأقسام التشغيلية: متاح للاطلاع على العمليات المرتبطة بالتصنيع.
- **ما يُمنع منه:**
  - ❌ **إدارة المخالفات والرقابة** (`/violations-admin`): محجوبة ومخفية تماماً من القائمة الجانبية. وفي حال محاولة الدخول المباشر للرابط، يتم منعه فوراً بواسطة `<ProtectedRoute allowedRoles={['admin']}>` وتظهر له رسالة "غير مصرح بالدخول لهذا القسم".
  - ❌ تعديل المعاملات المالية الحساسة أو صرف الرواتب.

#### ب. مدير الإنتاج (`production@mavex.com`)
- **ما يراه ويتحكم فيه:**
  - لوحة التحكم العامة (`/`).
  - قسم الإنتاج (`/production`): خطوط التشغيل، جدول أوامر التصنيع، إضافة أمر تشغيل جديد، وتحديث نسب الإنجاز.
- **ما يُمنع منه:**
  - ❌ صفحة إدارة المخالفات والرقابة (`/violations-admin`).
  - ❌ تعديل القيود المالية الخاصة بقسم المحاسبة.

#### ج. مدير الصيانة والتشغيل (`maintenance@mavex.com`)
- **ما يراه ويتحكم فيه:**
  - لوحة التحكم العامة (`/`).
  - قسم الصيانة (`/maintenance`): مؤشر جاهزية الماكينات (Uptime)، سجل الصيانة الوقائية، استقبال طلبات الأعطال وإغلاقها.
- **ما يُمنع منه:**
  - ❌ صفحة إدارة المخالفات والرقابة (`/violations-admin`).

#### د. مدير السلامة والصحة المهنية (`safety@mavex.com`)
- **ما يراه ويتحكم فيه:**
  - لوحة التحكم العامة (`/`).
  - قسم السلامة (`/safety`): سجل الحوادث والإصابات، جولات التفتيش على مهمات الوقاية (PPE)، وجاهزية أنظمة الإطفاء.
- **ما يُمنع منه:**
  - ❌ صفحة إدارة المخالفات والرقابة (`/violations-admin`).

#### هـ. مدير التخطيط والمستودعات (`warehouse@mavex.com`)
- **ما يراه ويتحكم فيه:**
  - قسم المستودعات (`/planning-warehouse`): أرصدة الخامات، تتبع حركات الصرف والإضافة، شجرة الأصناف، ومتابعة حد إعادة الطلب.
- **ما يُمنع منه:**
  - ❌ صفحة إدارة المخالفات والرقابة (`/violations-admin`).

#### و. مدير الحسابات والمالية (`finance@mavex.com`)
- **ما يراه ويتحكم فيه:**
  - قسم الحسابات والمالية (`/finance`): الإيرادات، التكاليف التشغيلية، التدفقات النقدية، ومسيرات الرواتب.
- **ما يُمنع منه:**
  - ❌ صفحة إدارة المخالفات والرقابة (`/violations-admin`).

---

### 3.3. أعضاء الأقسام والفنيون (`department_member`)
- يشاهدون العمليات الخاصة بالقسم الذي يعملون به.
- يملكون صلاحية إدخال قراءات أو تحديث مراحل التنفيذ (مثل تقدم مرحلة الدهان أو التجميع).
- لا يملكون صلاحية الحذف أو التعديل الهيكلي أو اعتماد التقارير الشهرية.
- ممنوعون تماماً من الوصول إلى `/violations-admin`.

## 5. المنطق البرمجي لكيفية عمل المنظومة (Technical Implementation)

### 5.1. حماية الروابط في الواجهة الأمامية (`ProtectedRoute.jsx`)
```jsx
// client/src/components/common/ProtectedRoute.jsx
if ((allowedRoles && allowedRoles.length > 0) || requiredDepartment) {
  const hasPermission = canAccess(allowedRoles || [], requiredDepartment);
  if (!hasPermission) {
    return <AccessDeniedScreen />; // عرض شاشة تنبيه: غير مصرح بالدخول لهذا القسم
  }
}
```

### 5.2. فلترة عناصر القائمة الجانبية (`Sidebar.jsx`)
```jsx
// client/src/components/layout/Sidebar.jsx
{NAV_ITEMS.map((item) => {
  // إخفاء الروابط الخاصة بالأدمن تلقائياً عن باقي المستخدمين
  if (item.adminOnly && !isAdmin) {
    return null;
  }
  return <NavLink key={item.path} to={item.path}>...</NavLink>;
})}
```

### 5.3. حماية المسارات في الخادم (`server/src/middleware/authorize.js`)
```javascript
// server/src/middleware/authorize.js
function authorize(allowedRoles = [], options = {}) {
  return (req, res, next) => {
    const userRole = normalizeRole(req.user.role);

    // الأدمن يمتلك صلاحية تجاوز الفحص (Superuser Bypass)
    if (userRole === ROLES.ADMIN) {
      return next();
    }

    // التحقق من توافق دور المستخدم مع الأدوار المصرح بها
    if (allowedRoles.length > 0 && !allowedRoles.includes(userRole)) {
      return next(new ForbiddenError('ليس لديك صلاحية الدور المطلوب لتنفيذ هذا الإجراء'));
    }

    // التحقق من نطاق القسم إن وُجد
    if (options.department && req.user.departmentId !== options.department) {
      return next(new ForbiddenError('غير مصرح لك بالوصول لبيانات هذا القسم'));
    }

    next();
  };
}
```

## 6. خلاصة تدفق المستخدم (User Journey Summary)

1. **تسجيل الدخول:** يدخل المستخدم البريد وكلمة المرور عبر `/login`.
2. **المصادقة:** يتحقق السيرفر من كلمة المرور المشفرة في **MongoDB** ويصدر رمز **JWT**.
3. **تحديد الصلاحية:** يقرأ الفرونت إند دور المستخدم (`admin` / `department_manager` / `department_member`) والقسم التابع له.
4. **تخصيص الواجهة:**
   - إذا كان **`admin`**: تظهر له كل الأقسام كاملة بالإضافة إلى قسم المخالفات والرقابة.
   - إذا كان **مدير قسم**: تظهر له أقسام المصنع التشغيلية ويُحجب عنه قسم المخالفات والرقابة التابع للإدارة العليا.
   - إذا حاول أي مستخدم كتابة رابط غير مصرح به في المتصفح يدوياً، يتم اعتراضه فوراً وعرض شاشة منع الدخول مع زر للعودة للرئيسية.
